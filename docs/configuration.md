## 环境依据

源码直接导入外部包 `yaml`（PyYAML）和 `ultralytics.YOLO`；`os`、`shutil`、`random` 来自 Python 标准库。`.idea/misc.xml` 中的 Python 3.10 是历史 IDE 设置，不等于经测试的最低版本或唯一兼容版本。PyTorch 和 GPU 支持应按选定 Ultralytics 版本及设备条件核验。

本次未安装依赖，没有声称某组版本可运行。维护者应在隔离环境中安装并验证选定版本，保存实际环境导出；未完成版本核验前不把未锁定安装命令作为可靠复现配方。

## 运行前检查

1. 使用独立仓库副本，备份原 YAML、`datasets_formatted/` 和已有实验产物。核对输出路径没有重要的唯一文件。
2. 确认 Dataset 来源和使用权限；核对图片、标签、类别编号、空标签规则和损坏文件。
3. 确认目标是脚本现有 17 类还是另一个经批准的方案。若需 3 类，应先申请独立代码变更；只编辑 YAML 会被脚本覆盖。
4. 优先准备已划分的 images/train、images/val 与对应 labels；确认两组非空且无同源泄漏。保存划分清单。
5. 保存提交 SHA、环境版本、设备信息和基础权重校验值；确认网络下载是否允许。
6. 确认训练会重建输出、覆盖 YAML 并消耗计算资源后，按根 README 启动。此处是运行指南，本次未执行。
7. 启动后检查生成 YAML 的类别和路径；结束后检查完整日志、实际保存目录、CSV 与权重。失败不能只依赖退出码判定。

## 实验记录最小字段

实验编号、执行人和日期、代码 SHA、数据来源/版本及校验值、训练与验证文件清单、类别映射、基础权重校验值、完整环境、训练参数、实际输出位置、指标含义、异常与结论。未知字段记录“未记录”，不要用当前值替代历史值。

## 变更与恢复

需求或类别变更应同时更新需求说明、设计类别表、相关用例和追踪矩阵；依赖或参数变更应保留前后环境及新实验记录。合并前检查文档差异和证据链接。

恢复数据必须使用事前备份；Git 无法恢复未被版本管理且被 `shutil.rmtree()` 删除的唯一文件。回退代码提交不代表回退训练数据或环境。历史产物与新产物分开保留，不覆盖历史证据。
