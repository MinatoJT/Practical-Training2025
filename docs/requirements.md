# 软件需求说明

标识：PPE-SRS。版本 0.1，待评审。证据基线及标准使用边界见 [文档管理说明](README.md)。
源代码基线：`4bb13b0391a2f2581aec488c305a6ddaabde6ac8`；本版修订日期：2026-10-03。

## 范围与用户

服务于实训人员在本地准备 PPE 检测图像数据并调用 Ultralytics 完成训练。当前实现不提供摄像头采集、实时告警、Web/API 服务、账户体系、模型部署或独立推理入口。以下为从代码整理的需求候选和复现约束，不能代替已批准的用户需求。

## 功能需求与核查准则

| 标识 | 需求候选 | 核查准则 |
|---|---|---|
| PPE-FR-01 | 整理已划分的图像集 | 发现 `Dataset/images/train` 与 `val` 时，分别复制允许扩展名的图像，保持划分 |
| PPE-FR-02 | 为未划分图片建立训练与验证分组 | 依次搜索 Dataset 根、images、JPEGImages；选择第一个含图片目录，训练数为 floor(N×0.8)，其余验证 |
| PPE-FR-03 | 按同名文件查找并复制标签 | 按设计文档中的三个路径优先级寻找 `.txt`，复制到对应 labels 子目录 |
| PPE-FR-04 | 生成训练配置 | 写入格式化数据绝对路径、train/val 相对路径及脚本内 17 类表，覆盖根 YAML |
| PPE-FR-05 | 加载基础模型并启动训练 | 优先用本地 `yolov8n.pt`；调用 `YOLO(...).train(...)` 并传入已记录参数 |
| PPE-FR-06 | 报告训练结果或错误 | 成功后打印实际保存路径；异常时打印错误信息。退出状态可靠性是已知缺口 |

FR-03 仅描述现有复制行为，不表示缺失或格式错误的标签被有效拦截；FR-02 不表示随机划分可复现。

## 数据与外部接口

输入为本地图像、同名 YOLO 检测标签、基础模型权重及 Python 依赖环境。允许图像扩展名为 `.jpg`、`.jpeg`、`.png`、`.bmp`，不区分扩展名大小写；搜索仅限已明确列举的目录层级，不递归扫描任意子目录。

标签格式需由数据维护者核验为 `class x_center y_center width height`，坐标归一化且类别编号与目标类别表一致。该规则是数据准备要求，脚本未实现解析或边界校验。背景图可否没有标签、空标签的规则及异常样本处理均须先确定。

输出为 `datasets_formatted/`、被重写的 `sh17_config.yaml` 和 Ultralytics 实验产物。模型和数据不提供服务接口；终端日志是现有反馈通道。

## 质量目标与限制

| 标识 | 目标或约束 | 当前状态 |
|---|---|---|
| PPE-QR-01 | 数据、配置、环境和训练产物可追踪到同一实验 | 缺数据清单、环境锁定和明确类别对应关系，待补齐 |
| PPE-QR-02 | 重复实验采用相同数据划分 | 自动划分未固定随机源；建议使用已划分输入并保存清单 |
| PPE-QR-03 | 输出重建不损失唯一数据副本 | 现有代码会删除输出目录；运行前必须备份并使用隔离副本 |
| PPE-QR-04 | 训练失败可可靠识别 | 现有异常处理仅打印；需结合日志和产物判断，待整改 |
| PPE-QR-05 | 模型性能符合使用目的 | 未约定阈值；不能按历史数值自行宣布验收 |

## 待确认的验收条件

类别范围（3 类还是 17 类）、每类样本量与标注质量、训练/验证/独立测试的划分、召回率和误报容限、每类 AP 与总体 mAP 门槛、目标设备和时延，以及数据与权重的使用授权，均须维护者确认。实验指标目标在批准前保持“待定”，不伪造数值或以历史成绩倒推门槛。
